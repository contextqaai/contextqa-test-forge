# My custom-agent brief

Copy this worksheet into a private project note and replace the prompts. This is a design/review document, not a loadable CLI profile or an installed skill.

| Decision | Fill in for your agent |
|---|---|
| Agent name and owner | Who maintains it and who acts on its output? |
| One useful outcome | What business decision or task will it support? |
| Trigger and scope | Explicit request, selected ticket or reviewed event; which app/version/role? |
| Success and negative control | What must be true, and what deliberately wrong condition must be caught? |
| ContextQA capabilities to reuse | Selected product capabilities and native cases/plans/settings |
| Confirmed interfaces | Exact supported tools/operations, scoped IDs and account access; name unresolved bindings |
| Your customization | Priorities, business rules, output format and handoff destination |
| Permitted actions | Read/prepare by default; identify any separately approved writes/runs |
| Human review | Named reviewers, review packet, accept/revise/escalate decisions and response path |
| Orchestration | Dependencies, target environment, test data, run bounds and owner-authorized budget |
| Evidence | Source, configuration, accepted run, selected results, assertions and known gaps |
| Change policy | What invalidates approval? What requires a new business decision or rerun? |
| Optimization | Baseline, reviewer effort, defect signals, repeated use, known cost and next experiment |
| Publication and release | Who accepts/merges/publishes? Which actions remain manual? |

Readiness: the team can explain the rule, inspect a failure, revise the workflow and repeat it. A complete worksheet alone does not authorize execution or establish that any result passed.
