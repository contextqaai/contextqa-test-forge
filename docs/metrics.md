# Time, tokens and evidence

`src/cli.js` prints elapsed milliseconds for that local command. `examples/demo.js` writes `metrics.json` for six synthetic source imports and 18 project exports. These measurements exclude dependency installation, browser execution, human review and AI drafting. They are hardware/cache dependent. Zero token counts are valid only with `modelCalls:0` and `usageSource:no-model-calls`.

`examples/benchmark.json` is a checked-in observation from the local synthetic generation benchmark, not a performance guarantee. Reproduce with `node examples/demo.js output/your-new-run`. The full generated metrics include source/contract hashes and exported test counts. Runner timing and outcomes come from the actual test runners and CI, not the generation report. Use source IDs/hash and contract hash to correlate these records.

Optional AI drafts have separate provider/model, call count, latency, content hash and provider-reported token fields. Missing provider usage stays unknown. Estimated cost is null until independently calculated from the provider's current price and actual billing categories. No keys or submitted source text are printed in console metrics; draft files themselves contain private model output and must be protected.

The coding agent's total conversation token count, total engineering time, other providers' internal work and a human/Claude comparison baseline are not observable by this package. They are not reported as zero or invented. Actual end-to-end authoring and maintenance experiments require a timer, a controlled task and the real baseline logs.

The primary ContextQA client additionally records request count and elapsed transport milliseconds. Its model-token and billed-cost fields remain `null`; API request count, `aiDuration` or browser duration is not a monetary invoice or token meter. The mocked authoring example labels its 11 requests as mocked and records zero live/model calls; its three exports are not hosted execution evidence. Source/bundle/profile hashes and durable authoring/run journals provide separate correlation records.

The checked-in benchmark only establishes that the fixture importer/exporter ran. Separately, [GitHub Actions run 40601770497](https://github.com/contextqaai/contextqa-test-forge/actions/runs/40601770497) passed on October 27, 2026 for commit `4f6417f2badf5b83c4d6ab0bb276c0d583c0a492`: unit/generation checks plus the GitHub fixture executed in Playwright, Selenium and WebdriverIO. The observed unit job was about six seconds and workflow elapsed time about 52 seconds; those historical timings are not local install/run guarantees and are not included in `benchmark.json`. This does not establish that later checkout changes passed.

That run covered the positive synthetic browser path, not the subsequently added negative-control harness. Live Jira, Linear, TestRail, Xray, GitHub tenant reads, paid AI requests and ContextQA SaaS execution remain unverified by those fixtures. [Real testing](real-testing.md) gives fresh install, deliberately failing assertion and live acceptance procedures. Keep actual runner logs separate from generation's `executed:false` metrics and record new evidence only after a run completes.
